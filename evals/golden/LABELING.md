# Инструкция по разметке Golden Dataset

Цель: получить **независимые** экспертные оценки 24 задач бэклога. По ним мы:
1. проверим согласованность экспертов (каппа Коэна / взвешенная каппа);
2. построим эталонное ранжирование и будем сравнивать с ним агента (NDCG@k, порог 0.90).

Время: 40–60 минут на эксперта.

## Порядок работы
1. Скопируйте `labeling/template.csv` в `labeling/expert-<фамилия>.csv`.
2. Прочитайте `labeling/tasks.md` (карточки задач) и
   `skills/backlog-prioritization-engine/references/scoring-rubric.md` (веса и шкалы).
3. Заполните по строке на задачу. **Не обсуждайте оценки с другими экспертами до сдачи файла**,
   иначе каппа измерит договорённость, а не независимое мнение.
4. Не запускайте агента и `priority.py` на этих задачах до сдачи: результат агента не должен
   влиять на эталон.
5. Проверьте файл: `python3 -I evals/golden/agreement.py --validate labeling/expert-<фамилия>.csv`.

Файл открывается в Excel (разделитель `;`, UTF-8). Сохраняйте как CSV UTF-8.

## Колонки

| Колонка | Значения | Как ставить |
|---|---|---|
| `critical` | `yes` / `no` | `yes`, если выполняется любой порог: активный P1-инцидент / простой ключевой системы > 15 мин; CVSS ≥ 9.0; обязательный юридический срок < 30 дней; прямой финансовый риск > 500 000 руб. |
| `critical_reason` | текст | обязательно при `yes` |
| `impact_scaling` … `impact_tech_risk` | 0–5 | по рубрике; при `critical = yes` оставьте пустыми |
| `urgency` | 1–5 | только по стоимости задержки (Cost of Delay), не по тону запроса |
| `relevance` | 0–3 | итоговое суждение «насколько задача должна быть наверху ближайшего плана»: **3** обязательно в топе, **2** желательно, **1** можно позже, **0** не делать. При `critical = yes` оставьте пустым |
| `comment` | текст | по желанию: что смутило, чего не хватило |

Правила Evidence Tiers применяйте так же, как агент: Impact 4–5 только при наличии доказательств
в описании (ссылки на Confluence / Google Docs, ADR, явные замеры с источником). Сведения из
блока «Дополнительно известно» в карточке считайте подтверждёнными фактами.

Ничего не пересчитывайте по формуле: `relevance` — ваше суждение, а не вычисление. Эталон
должен отражать мнение эксперта, а не повторять формулу, которую мы проверяем.

## Что дальше
`python3 -I evals/golden/agreement.py labeling/expert-*.csv` выводит каппу по каждому полю и
список расхождений. Задачи с расхождением ≥ 2 балла по `relevance` или `urgency` и с разным
`critical` разбираются на встрече (adjudication). Эталон собирается только после разбора.
